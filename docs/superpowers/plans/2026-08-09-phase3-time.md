## Context

The master design spec ([`2026-08-01-desktop-app-design.md`](file:///Users/kahuku-air/Developer/CanvasCLISwift/docs/superpowers/specs/2026-08-01-desktop-app-design.md), §4, §5.2, §5.3, §6, §9) defines **Phase 3 — Time** as:
- **Calendar** (month, week, and agenda modes over assignment due dates and course calendar events, color-coded by course accent color).
- **To-Do triage** (three triaged sections: *Missing*, *Due this week*, and *Awaiting grade*).
- **Due-soon surfaces** in both scenes (Dashboard due-soon strip, popover due-soon section, `.dueSoon` `ChangeRecord` generation within 24-hour due windows).

Phase 0 (foundation), Phase 1a (Dashboard + Sandbox), Phase 1b (Course workspace read features), and Phase 2 (Communication / Inbox / Discussions / Notifications) are completed and merged into `main`.

**Current stubs this plan fills:**
- [`MainWindowView.swift:85`](file:///Users/kahuku-air/Developer/CanvasCLISwift/CanvasApp/Views/Window/MainWindowView.swift#L85) renders `ComingSoonView(title: "Calendar", phase: "Phase 3")` — replaced by the full `CalendarView`.
- [`MainWindowView.swift:86`](file:///Users/kahuku-air/Developer/CanvasCLISwift/CanvasApp/Views/Window/MainWindowView.swift#L86) renders `ComingSoonView(title: "To-Do", phase: "Phase 3")` — replaced by `ToDoView`.
- Dashboard and Popover due-soon surfaces wired to real assignment due dates and planner items.

Goal after this plan: `CalendarView` offers a 3-mode (Month, Week, Agenda) interactive view color-coded by course accent; `ToDoView` categorizes assignments and planner items into *Missing*, *Due this week*, and *Awaiting grade*; `.dueSoon` change records fire notifications for items due within 24 hours; and all features are fully test-covered and walkable in `DEMO` mode.

## Architecture

New decode/predicate logic (planner item decoding, calendar event decoding, date-range filtering, due-soon window calculation, awaiting-grade triaging) lands as **pure, XCTest-covered functions** in `CanvasCore`/`CanvasData`. New sync/upsert logic is covered in `CanvasDataTests` using an in-memory `ModelContainer` (`CanvasStore.container(inMemory: true)`) + `DEMO` `APIClient` harness. Request shaping for the new `GET /api/v1/planner/items` and `GET /api/v1/calendar_events` calls is covered in `CanvasCoreTests` with a `URLProtocol` stub.

SwiftUI stays a thin consumer: value-driven `public struct … : View` components in `CanvasUI`, small per-surface `@MainActor @Observable` or `ObservableObject` view-models in `CanvasApp`, following existing architecture.

**Data flow additions.** `SyncEngine` gains the `.planner(start: Date, end: Date)` sync scope (15-minute TTL) which fetches both planner items and calendar events for the date window. `CanvasRepository` exposes queries for planner items, calendar events, combined calendar timeline items, and triaged to-do items (*Missing*, *Due this week*, *Awaiting grade*).

## Global Constraints

- **Test framework:** XCTest only, `@testable import`, mirroring previous phases. Every testable behavior (decoding, request shaping, date range queries, triaging logic, due-soon change detection) goes in `CanvasCore`/`CanvasData`.
- **Demo verifiability:** every new surface must be walkable end-to-end with `CANVAS_TOKEN=DEMO`. `MockData` expands to return synthetic planner items and calendar events spanning current, past, and upcoming weeks.
- **Awaiting grade rule (spec §3.1):** A submission with `workflowState == "graded"` and `score == nil` is a **muted/hidden grade**. It belongs in *Awaiting grade*, not recently graded. Also, work submitted without a final grade or score is marked awaiting grade.
- **Design tokens & palette:** Reuse `Sources/CanvasUI/DesignTokens.swift` and course accent colors (`/users/self/colors` or course code hash).
- **SF Symbols only:** Use standard SF Symbols (`calendar`, `checklist`, `exclamationmark.triangle`, `clock`, `checkmark.circle`, `calendar.badge.clock`, `chevron.left`, `chevron.right`).

// In Sources/CanvasCore/APIClient.swift
public func plannerItems(start: Date, end: Date) async throws -> [PlannerItem] {
    if isDemo {
        return MockData.plannerItems
    }
    let formatter = ISO8601DateFormatter()
    let path = "/api/v1/planner/items?start_date=\(formatter.string(from: start))&end_date=\(formatter.string(from: end))&per_page=100"
    return try await getPaginated(path)
}

public func calendarEvents(contextCodes: [String], start: Date, end: Date) async throws -> [CalendarEvent] {
    if isDemo {
        return MockData.calendarEvents
    }
    let formatter = ISO8601DateFormatter()
    var path = "/api/v1/calendar_events?type=event&start_date=\(formatter.string(from: start))&end_date=\(formatter.string(from: end))&per_page=100"
    for code in contextCodes {
        path += "&context_codes[]=\(code)"
    }
    return try await getPaginated(path)
}
